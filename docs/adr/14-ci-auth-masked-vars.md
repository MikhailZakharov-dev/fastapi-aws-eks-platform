# ADR: CI→AWS auth — masked CI-variables, в проде OIDC (тема 14)

- **Статус:** принято (учебный компромисс)
- **Контекст:** джобе GitLab нужен push в ECR. Варианты: (A) долгоживущий ключ
  IAM-юзера в masked+protected CI-variables; (B) OIDC federation — GitLab куёт
  короткоживущий JWT, STS `AssumeRoleWithWebIdentity` меняет его на временную
  тройку (key+secret+session, ~1ч).
- **Решение:** A для этого репо.
- **Почему допустимо здесь:** blast radius мал — отдельный юзер
  `gitlab-ci-ecr-push` c least-privilege (только push в один репо: нет pull,
  нет перезаписи SHA-тегов — immutable); соло-репо без коллабораторов; аккаунт
  учебный, всё пересоздаваемо. Ключи masked (не светятся в логах) + protected
  (выдаются только пайплайнам protected-ветки main).
- **Почему в проде OIDC:** статический ключ — переносимый секрет: утёк →
  работает откуда угодно до ручной ротации; аргумент «нас не будут ломать» —
  security-by-obscurity, не принимается. При OIDC красть нечего: секрет нигде
  не лежит, токен куётся на лету и протухает; злоупотребление требует запуска
  джобы в самом репо (видно в аудите, отзывается доступом).
- **Отработка паттерна:** federation руками — тема 21 (IRSA): тот же ход
  «JWT → проверка подписи по JWKS → временные креды», личность — ServiceAccount
  пода вместо CI-джобы.
