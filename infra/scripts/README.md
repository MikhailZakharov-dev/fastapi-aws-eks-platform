# infra/scripts

## sync-values.sh

Переносит в gitops-репозиторий два значения, которые Terraform создаёт заново при
каждом поднятии стенда:

| значение | откуда | куда |
| --- | --- | --- |
| ARN секрета с паролем базы | `terraform output rds_secret_arn_for_eso` | `charts/secrets/values-dev.yaml` |
| адрес инстанса базы | `terraform output rds_endpoint` | `charts/talk-booking/values-dev.yaml` |

### Зачем это нужно

Пароль базы ведёт сам RDS в Secrets Manager, и при пересоздании инстанса секрет
получает **новый ARN** — в нём генерируемый идентификатор. Адрес инстанса тоже может
смениться. Оба значения попадают в желаемое состояние кластера, то есть в git, и потому
не могут подставляться автоматически при синхронизации.

Пока значения не обновлены, поднятый стенд выглядит рабочим, но приложение не стартует:
`ExternalSecret` не находит секрет по старому ARN, Secret не создаётся, под падает с
`CreateContainerConfigError`. Симптом находится в кластере, а причина — в двух строчках
в другом репозитории.

### Когда запускать

**После каждого `make up`**, до того как ждать работающее приложение.

```bash
./scripts/sync-values.sh     # из каталога infra
# или
make values
```

Скрипт ничего не коммитит — только правит файлы и показывает, что изменилось.
Коммит и push остаются за человеком, потому что это изменение желаемого состояния.

### Если gitops-репозиторий лежит в другом месте

По умолчанию скрипт ищет его рядом с `talk-booking`. Иначе:

```bash
GITOPS_DIR=/путь/к/talk-booking-gitops ./scripts/sync-values.sh
```

### Что он проверяет

- оба файла на месте, иначе сообщает и выходит;
- `terraform output` вернул непустые значения, иначе подсказывает поднять стенд;
- **после каждой подстановки** проверяет, что значение реально записалось. `sed`
  завершается успешно, даже когда ничего не заменил, поэтому переименованный ключ или
  изменившийся отступ иначе оставили бы старое значение молча.
